# 数据上传工作流程

**来源项目**: 公司知识库-资料上传入口
**提取日期**: 2026年1月9日
**知识类型**: 工作流程

---

## 📋 流程概述

本文档描述了从文件上传到RAGFlow知识库的完整工作流程，包括文件处理、分类、验证和上传等步骤。

---

## 🔄 核心流程

### 阶段1: 文件接收和预处理

1. **文件上传**
   - 接收单文件或批量上传
   - 验证文件格式和大小
   - 计算文件 hash（用于去重）

2. **文件存储**
   - 按日期组织存储：`uploads/2025/11/29/`
   - 存储路径：`/mnt/data/ragflow-upload/`（机械硬盘）
   - 未来可扩展为 NFS 或 MinIO

3. **文件预处理**
   - 文档解析（PDF/Word/文本）
   - Excel → 结构化转换模块
   - 保留原文件

---

### 阶段2: 智能分析和建议

1. **智能命名建议**
   - 使用 LLM 分析文件名
   - 根据公司命名规则建议优化文件名
   - 提供命名建议API

2. **智能分类建议**
   - 使用 LLM 分析文档内容
   - 自动推荐最合适的知识库分类
   - 支持分类：制度流程、产品方案、项目案例、技术资料、运维支持、合同管理、投标事业部

3. **文档内容分析**
   - 敏感词检测
   - 命名规则校验
   - 版本冲突检测

---

### 阶段3: 元数据提取和验证

1. **元数据提取**
   - 自动提取文档元数据
   - 包括：标题、作者、创建时间、修改时间等

2. **数据验证**
   - 敏感词校验
   - 命名规则校验
   - 版本冲突检测
   - 文件完整性校验

---

### 阶段4: RAGFlow集成

1. **知识库映射**
   - 根据分类名称映射到知识库 ID
   - 使用配置文件或默认映射
   - 支持动态更新映射表

2. **文档上传**
   - 调用 RAGFlow API 上传文档
   - 附加元数据和标签
   - 返回任务 ID

3. **状态监听**
   - 轮询文档解析状态
   - 等待解析完成
   - 更新任务状态

---

### 阶段5: 任务管理和通知

1. **任务管理**
   - 创建任务记录
   - 更新任务状态
   - 记录操作日志

2. **状态通知**
   - 基于状态变化触发通知
   - 支持邮件/企业微信/钉钉
   - 预留审批流程hook

---

## 🎯 关键决策点

### 决策1: 文件存储方案

**选择**: 本地文件系统

**理由**:
- 与现有项目一致，简单可靠
- 按日期组织，便于管理
- 未来可扩展为 NFS 或 MinIO

**备选方案**: MinIO对象存储

---

### 决策2: LLM服务选择

**开发环境**: Ollama（免费）

**生产环境**: 通义千问（需要 API Key）

**理由**:
- 开发环境使用免费方案降低成本
- 生产环境使用商业方案保证稳定性

---

### 决策3: 数据库选择

**选择**: SQLite

**理由**:
- 与现有项目一致
- 简单可靠，无需额外配置
- 适合中小规模数据

---

## ⚠️ 注意事项

1. **文件路径**
   - 必须使用绝对路径
   - 确保文件存在且有读取权限

2. **Token管理**
   - Token 可能有时效性，需要定期更新
   - 建议实现 Token 自动刷新机制

3. **知识库映射**
   - 需要根据实际创建的知识库更新映射表
   - 可以通过 API 获取实际的知识库 ID

4. **错误处理**
   - 实现重试机制
   - 记录详细的错误日志
   - 提供清晰的错误提示

---

## 📊 流程优化建议

### 1. 异步处理

对于大文件或批量上传，建议使用异步处理：
- 使用任务队列（如 Celery）
- 后台处理文件解析和上传
- 通过WebSocket或轮询通知前端

### 2. 缓存机制

- 缓存LLM分析结果
- 缓存知识库映射
- 减少重复计算

### 3. 监控和告警

- 监控上传成功率
- 监控处理耗时
- 失败率告警
